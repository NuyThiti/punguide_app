# สิ่งที่หลังบ้านต้องอัปเดต

รวมจุดที่แอปวาดตามดีไซน์ได้แล้ว แต่ **ยังส่งขึ้น/อ่านกลับไม่ได้** เพราะ API ยังไม่มีที่เก็บ
หรือยังตอบผิด — เรียงจากที่บล็อกงานตอนนี้ก่อน

อัปเดตล่าสุด 2026-09-23 · ตรวจกับ dev API

> ข้อ 2 และ 3 **ปิดแล้ว** — หลังบ้านเพิ่มฟิลด์ให้ครบและ client ต่อเสร็จแล้ว
> ที่เหลือคือข้อ 1 (บั๊ก 500), **1.2 (ใหม่ 2026-09-23 — โพสต์หาย Near Me)**, 4 และ 5

## 1. บั๊กที่บล็อกอยู่ตอนนี้

### 1.1 `GET /trips/:id` ตอบ 500 ทุกทริป

เส้น list ปกติ แต่รายตัวพังทั้งหมด ทำให้หน้าแผน (`/trips/:id/edit`) และหน้ารายละเอียด
ทริปโหลดไม่ขึ้นเลยบน simulator ขึ้น `โหลดทริปไม่สำเร็จ`

```
GET /trips            → 200  (15 ทริป)
GET /trips/:id        → 500  {"statusCode":500,"message":"Internal server error"}
GET /trips/:id/budget → 500
```

ตรวจแล้วกับ id ทั้ง 15 ตัวที่ได้จาก `GET /trips` — 500 หมดทุกตัว
`GET /trips/mine` ใช้ได้ (401 ถ้าไม่มี token ซึ่งถูกแล้ว)

**ผลกระทบ:** แท็บสรุปงบที่เพิ่งทำเสร็จ (TEC-1085) ยังไม่ได้ verify กับข้อมูลจริงสักครั้ง

**สาเหตุ (ตรวจเมื่อ 2026-09-20):** entity map `trips.budget_currency` แล้ว แต่คอลัมน์
ยังไม่มีในฐานข้อมูล —

```sql
select column_name from information_schema.columns
where table_name='trips' and column_name in ('budget_currency','budget_amount_max','num_people');
-- budget_amount_max
-- num_people
```

ทุก SELECT บน `trips` จึงพัง ซึ่งอธิบายว่าทำไม 500 ทั้ง `GET /trips` และ `GET /trips/:id`
ตรงกับที่เอกสารฝั่งหลังบ้านหมายเหตุไว้เองว่ายังไม่ได้รัน migration —
`npm run migration:run` น่าจะจบ (ตอนนี้มีสองตัวรอ: `AddTripBudgetCurrency` และ
`AddTripLinkedTrip`)

### 1.2 โพสต์ (`type=content`) ได้ `distanceKm=20015` ทำให้ `sort=nearest` จัดลำดับผิด

**พบ 2026-09-23 · บล็อกอยู่**

โพสต์ทุกใบคืน `distanceKm: 20015` และไม่มี `destinationPlace` แท็บ **Near Me**
บนหน้า ไปกัน เรียงด้วยเลขนี้ โพสต์จึงจมท้ายสุดเสมอ **ต่อให้โพสต์อยู่ย่านเดียวกับ
หมุดที่ผู้ใช้เลือก** ผลคือผู้ใช้แทบไม่เห็นโพสต์บนบอร์ดเลย

จาก `GET /trips?lat=13.757325&lng=100.495141` (หมุด = เขตพระนคร):

| id | type | destination | destinationPlace | placeCount | distanceKm |
|---|---|---|---|---|---|
| `0ac1d897-…53ff` | content | พระนคร กรุงเทพฯ | **ไม่มี** | 7 | **20015** |
| `271ed6ab-…ade2` | content | พระนคร กรุงเทพฯ | **ไม่มี** | 1 | **20015** |
| `6b9af9d4-…6089` | plan_trip | น่าน | มี lat/lng | 15 | 549 ✅ |
| `0675c06a-…7a39c` | plan_trip | ญี่ปุ่น | มี lat/lng | 14 | 4506 ✅ |

**20,015 กม. = π × 6371 พอดี** คือระยะ antipode — ค่าที่ได้เมื่อพิกัดปลายทางเป็น
null แล้ว `acos` ถูก clamp ไปที่ `-1` ไม่ใช่ระยะที่วัดจากที่ใดจริง

ขัดกับเอกสาร filter feed ของหลังบ้านเองที่เขียนไว้ว่า:

> ทริปที่ปลายทางยังไม่ถูก resolve เป็นสถานที่จริงจะไม่มี field นี้ — **ไม่ใช่ `0`**

**มีข้อมูลพอจะแก้อยู่แล้ว:** `placeCount` ของโพสต์ทั้งสองใบ > 0 แปลว่ามี section ที่
ปักพิกัดไว้เรียบร้อย หลังบ้านจึงมีพิกัดในมือ แค่ยังไม่ได้เอามาใช้ตอนคิดระยะระดับทริป

**ที่ขอให้แก้**

1. `type=content` ที่มี section `location.status = confirmed` → คิด `distanceKm`
   จากพิกัดนั้น (ใกล้สุด หรืออันแรก แล้วแต่ทีมสะดวก)
2. ไม่มีพิกัดที่ใช้ได้เลย → **ตัด field `distanceKm` ทิ้ง** ห้ามส่ง `0` หรือ `20015`
3. `sort=nearest` จัดโพสต์ตามระยะจริง ส่วนแถวที่ไม่มีพิกัดไปอยู่**ท้ายสุด**
4. `plan_trip` ต้องไม่เปลี่ยนพฤติกรรม (น่าน 549 / ญี่ปุ่น 4506 เหมือนเดิม)

**ตรวจว่าแก้แล้วด้วย**

```bash
curl -sG "$BASE_URL/trips" -d "lat=13.757325" -d "lng=100.495141" -d "sort=nearest" \
  | jq '[.[] | {title, type, distanceKm}] | .[0:8]'
```

โพสต์ย่านพระนครต้องอยู่ต้น ๆ พร้อมระยะหลักสิบกิโลเมตรหรือน้อยกว่า และต้องไม่มี
`20015` โผล่มาอีก

**ฝั่งแอปทำอะไรไปแล้ว:** ใส่ guard ชั่วคราวใน `TripListItem.fromJson` ให้อ่าน
`distanceKm` เฉพาะแถวที่มี `destinationPlace` พร้อมพิกัดจริง ชิป `20015 Km` จึงไม่
ขึ้นบนการ์ดแล้ว **แต่ลำดับแก้ฝั่งแอปไม่ได้** เพราะ server เป็นคนเรียง — จะถอด guard
ออกเมื่อข้อนี้แก้เสร็จ

## 2. หน้า Create Post — ✅ ปิดแล้ว (backend อัปเดต 2026-09-20)

หลังบ้านตอบครบทั้งสี่ข้อ และฝั่ง client ต่อเสร็จแล้วในรอบเดียวกัน

| ข้อเดิม | สิ่งที่ได้มา | client ทำอะไร |
|---|---|---|
| 2.1 ฟิลด์ราย section | `visitedAt` `opensAt` `closesAt` `transportModes` `transportCost` `transportCurrency` `tripHack` ใน `contents[]` (JSONB เดิม ไม่ต้อง migrate) | ส่งขึ้นตอน publish และอ่านกลับตอนเปิดโพสต์เดิมมาแก้ |
| 2.2 คำโปรย | `description` (สาธารณะ) แยกจาก `specialNotes` (เจ้าของเท่านั้น) | ช่อง Trip Overview ย้ายไปเก็บที่ `description` |
| 2.3 งบ | `budgetCurrency` (ไม่ส่ง = THB) + `guestCount` ระดับบนสุด | dropdown สกุลเงินใช้งานได้จริง 6 สกุล |
| 2.4 Trip Activity เอง | `customStyles` / `customTransport` / `customConstraints` ใน create/update | ปุ่ม `+ เพิ่ม` บันทึกได้ ชิปที่เพิ่มเองกดลบได้ |

กติกาที่ client ยึดตาม:

- **เวลาเป็น wall-clock ไม่ใช่ timestamp** — ตรวจรูปแบบ `HH:mm` 24 ชม. ก่อนส่ง
  และ **ไม่ตรวจว่าปิดต้องหลังเปิด** (ร้านเปิด 18:00 ปิด 02:00 ผ่านได้)
- `transportCurrency` ส่งขึ้น **เฉพาะเมื่อมีจำนวนเงิน** — สกุลเงินลอย ๆ ไม่มีความหมาย
- `transportCost` ไม่ถูกนับรวมใน `totalBudget` ตามที่ระบุ — แอปไม่เอาไปคิดในสรุปงบ
- `budgetLimit` ยังเป็นยอดตามที่พิมพ์ ไม่คูณจำนวนคน — คำว่า "ต่อคน" เป็นการอ่านฝั่ง client
- `customStyles` ส่ง **เฉพาะเมื่อมีค่า** เพราะ PATCH merge ต่อ key: ส่ง `[]` = ล้างของเดิม
- `specialNotes` ที่ได้เป็น null หมายถึง **"ไม่ใช่ของเรา"** ไม่ใช่ "เจ้าของเว้นว่าง"

**แก้ของที่เคยทำผิดไว้ (2026-09-21):** ช่อง Trip Overview ในชีต Title เคยถูกเก็บลง
`specialNotes` ซึ่งเป็นโน้ตส่วนตัวที่คนอ่านคนอื่นไม่เห็นเลย ตอนนี้ย้ายไป `description`
ตามที่หลังบ้านระบุ — `specialNotes` ไม่ถูกส่งจากหน้านี้อีกแล้ว

**ยังไม่ได้ verify กับ server จริง** เพราะติดข้อ 1.1 ด้านล่าง — เทสต์ที่มีเป็น contract
test กับ widget test ที่ยืนยัน body ที่ส่งขึ้นและการอ่านกลับ

## 3. เชื่อมแผน + จำนวนสถานที่ — ✅ ปิดแล้ว (backend อัปเดต 2026-09-20)

| ข้อเดิม | สิ่งที่ได้มา | client ทำอะไร |
|---|---|---|
| `placeCount` | คืนทั้งใน list item และ detail | ชีตเลือกแผนแสดง `1 วัน • 11 สถานที่` โดยไม่ยิงรายแถว |
| เชื่อมแผน | `linkedTripId` เขียนได้ / `linkedTrip` อ่านกลับได้ | แผนที่เลือกในสเต็ป Next **ถูกบันทึกจริงแล้ว** (ก่อนหน้านี้เลือกแล้วหาย) |

กติกาที่ client ยึดตาม:

- `linkedTripId` มีสามสถานะ ใช้ `Patch<String>`: uuid = ผูก, `Patch.clear()` = ยกเลิก,
  ไม่ส่ง = คงเดิม ตอน publish ส่งเสมอ เพราะผู้ใช้เพิ่งตอบในชีตว่าจะเชื่อมอะไร
  รวมถึงตอบว่า "ไม่เชื่อม" ซึ่งต้องส่ง null ไม่ใช่เว้นไว้
- `linkedTrip` ที่หายไปอ่านเป็น "ไม่มีแผนให้แสดง" เฉย ๆ ไม่แยกสามกรณี
- `placeCount` ไม่มี fallback `?? 0` ที่ฝั่ง UI เพราะสัญญาบอกว่าไม่เคย absent
  (ตัว parser ยังกัน null ไว้ตามปกติของโมเดลอื่น)

**เทสต์จับบั๊กจริงได้ 2 จุดระหว่างต่อ:**

1. ถ้าแผนที่ผูกไว้ไม่อยู่ในหน้าลิสต์ที่โหลดมา กด `ตกลง` แล้ว **ยกเลิกการเชื่อมเงียบ ๆ**
   — แก้ให้ชีตถือ `PostTripLink` ทั้งก้อนแทน id เปล่า แล้ว fallback กลับไปที่ของเดิม
2. ถ้า `GET /trips/:planId` ล้มเหลว จะ **ยกเลิก publish ทั้งหมด** ทั้งที่ลิงก์ตกลงแล้ว
   — คำขอนั้นแค่ไปเอาจุดหมายของแผนมาเติมตอนโพสต์ไม่ได้ระบุเอง ตอนนี้เก็บลิงก์
   แจ้งเตือน แล้วไปต่อ

**ยังไม่ทำ:** กองรูปสมาชิก `+4` ในแถวแผน — ตามที่หลังบ้านแจ้งว่ายังไม่มีตาราง member
ในระบบ ชีตจึงวาด avatar เจ้าของคนเดียว

## 4. ของที่ยังไม่มี endpoint เลย

- **แท็บ `ห้องแชท`** — โผล่ในภาพอ้างอิงของหน้าแผน (Figma 1008-32393) เป็นแท็บที่ห้า
  ยังไม่ได้ทำเพราะไม่มีอะไรรองรับ
- **Reverse geocode** — ชีต Add Location ต้องใช้ที่อยู่ของพิกัดปัจจุบันใต้ปุ่ม
  "Use Current location" แต่ `/places` มีแค่ `autocomplete` / `details` / `suggest` /
  `suggestSections` / `search` / `byId` ไม่มีเส้นแปลงพิกัด → ที่อยู่
  ตอนนี้ยืมที่อยู่ของสถานที่ที่ใกล้กว่า 150 ม. แทน

## 5. เรื่องข้อมูลค้าง (ไม่ใช่บั๊กโค้ด แต่กวนผู้ใช้)

ปุ่ม "Creates post from Photos" ต้องสร้าง draft trip + อัปโหลดรูป **ก่อน** เรียก
`POST /trips/:id/contents/generate` ตาม contract ถ้าผู้ใช้กดแล้วออก จะเหลือ draft
trip แบบ private ค้างไว้ ตอนนี้ทริปพวกนี้โผล่ในชีต "เชื่อมกับแผนของฉัน" ด้วย —
เห็นเป็นแถวชื่อ `ร่างจากรูป` ที่บรรทัดรองเป็นพิกัด เช่น `37.7601, -122.5096`
เพราะไม่มีทั้ง schedule และ destination จริง

**ทางออกฝั่งหลังบ้าน (ถ้าจะทำ):** ไม่ส่ง draft ที่ยังไม่มี `contents` ใน `GET /trips/mine`
หรือมี job เก็บกวาด draft ที่ค้างเกิน N วัน
